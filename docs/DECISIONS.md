# Decisions

- **2026-10-06 · Electron + React + Remotion for the shell, native sidecar for capture.** Same split Screen Studio uses. Reason: Xcode is not installed and the disk has ~11 GB free; the UI and renderer are fully reusable when the recorder is swapped for Swift/ScreenCaptureKit. Preview and export share one composition so what you see is what renders.
- **2026-10-06 · Recorder is a stdin/stdout JSON-line sidecar.** Replaceable per platform (Windows later, spec §3). The app never links capture code.
- **2026-10-06 · Python + ffmpeg recorder is interim.** Limits: cannot exclude the control bar from the capture, no window/region capture, no system audio. All three need ScreenCaptureKit → Swift recorder once Xcode is available.
- **2026-10-06 · Pauses are metadata, not cuts.** Keeps raw media intact; editor can restore them later.
- **2026-10-06 · Features that don't work are not shown as buttons.** Editor lists unavailable features in plain text (spec §98).
- **2026-10-06 · Windows recorder is Python + ffmpeg too, standard library only (`recorder/narrate_win.py`).** Development moved to a Windows laptop, so Windows came before the Swift recorder. Same protocol, same `events.json`; the Electron app only switches script path, recordings folder, settings URLs and window chrome by `process.platform`. No pip packages: Win32 via ctypes, PNGs written by hand, so end users need only Python and ffmpeg (both per-user WinGet installs).
- **2026-10-06 · Windows: Desktop Duplication (`ddagrab`) first, GDI fallback.** Measured on a 1080p laptop: ddagrab ≈ 52 fps, gdigrab ≈ 24 fps. ddagrab is unavailable over RDP and on some drivers, so the recorder falls back automatically and records which path it used (`capture` in `events.json`).
- **2026-10-06 · Windows: video and audio in two ffmpeg processes, both on wall-clock timestamps, written to Matroska.** One process with gdigrab (wall clock) + dshow (uptime) deadlocked: ffmpeg starves the stream that is "behind". Separate processes also mean a microphone failure cannot stop the screen capture. Matroska keeps the wall-clock start time (fragmented MP4 resets it to 0) and survives a crash; finalisation remuxes to `screen.mp4` + `mic.wav`.
- **2026-10-06 · Crash recovery = journal + idempotent finalize, not a database.** The recorder appends to `events.partial.jsonl` and media are Matroska; `finalize` rebuilds the project from disk. Tested by killing the recorder and all ffmpeg processes mid-recording. Recovery is offered on the home screen with Restore / Discard (spec §61: never silently discard).
- **2026-10-06 · Camera is a third capture process and a third file, composited at render time.** `camera.mp4` on the shared wall clock (`cameraOffset`), shape/size/corner/mirror live in `RenderConfig`, so the overlay is editable after the fact and never baked into the screen (spec §10). Format is chosen from the camera's advertised list (largest ≤1080p at ≥24 fps, MJPEG preferred). A camera that fails to start downgrades to a warning; the screen recording continues.
- **2026-10-06 · System audio on Windows is captured in-process with WASAPI loopback, not through ffmpeg.** ffmpeg has no loopback input on Windows; "Stereo Mix" is usually absent; third-party virtual devices would need an installer. Raw COM through ctypes keeps the no-dependency rule. Measured sync error ≈ 2 ms over 3 s; silence is filled from the device position so the file never drifts when nothing plays. Opt-in per recording ("Computer sound: Record"), off by default (spec §15, §96).
- **2026-10-06 · Speech recognition is local Whisper in a private venv, installed on demand.** The recorder stays dependency-free; transcription is opt-in and explains the one-time ~300 MB download before running (spec §53 local-first, §64 offline afterwards). faster-whisper (CTranslate2) runs on CPU without a GPU stack; `base.en` is the default model for speed, swappable per call. The user's own Python installation is never modified.
- **2026-10-06 · A derivative asset = master + own cut list + config overrides.** The add-on spec's example stores `segments`; we store their complement as `cuts` so derivatives reuse the exact renderer, timeline and trim tools the master has — one editing model, zero special cases. Generation is deterministic from local signals; "Regenerate" replaces generated assets (manual tweaks to a generated asset survive until the user regenerates).
- **2026-10-07 · Smart zoom filters clicks by cursor dwell, not just by clustering.** A click only earns a zoom if the cursor had settled near it ~0.35 s before (add-on §10: meaningful clicks); nearby follow-up clusters within 3 s pan instead of zooming out and back in. Deterministic, renderer-side, no analysis file needed. To be tuned against real recordings.
- **2026-10-06 · Smart Director v1 is local signal processing, not an LLM.** ffmpeg silence/scene detection plus cursor and click maths already yield the proposals the add-on spec lists first (pauses, chapters, zooms, highlights), cost nothing, work offline (spec §53, §64) and are reproducible. Proposals are data in `analysis.json`; accepting them produces ordinary project edits, so a later AI layer only has to emit the same proposal shape.
- **2026-10-06 · One viewport model for every aspect.** The zoom "camera" works in absolute scale over the screen with a per-layout rest scale (`base`) and a frame size; landscape presets fit the screen, portrait/square presets crop it and rest on a lazily-smoothed cursor position. Same keyframe builder, same clamping, no special-case renderer per aspect — so derivative assets (add-on §4) only differ by config and segments.
- **2026-10-06 · `project.json` next to the media, autosaved, merged over defaults on load.** One small JSON per recording instead of a database: trivially portable, survives app upgrades (unknown new settings fall back to defaults), and the CLI exporter reads the same file. Written tmp + rename so it is never half-written.
- **2026-10-06 · Mic level meter is a recorder subcommand** (`meter`), streaming 0..1 at 10 Hz over stdout, stopped by closing stdin. Keeps all device access in the sidecar; the app never links audio code.
- **2026-10-06 · Hardware encoder is probed once and cached** (`%LOCALAPPDATA%\Narrate\encoder.json`, keyed by ffmpeg binary). NVENC → Quick Sync → AMF → libx264. The probe costs ~3 s; caching keeps "Record" fast (spec §95).
- **2026-10-19 · Self-contained Windows installer.** `npm run dist` copies a full Python 3.12 and gyan.dev ffmpeg/ffprobe (GPL, licence shipped beside them) into `resources/runtime`; the app exports `NARRATE_FFMPEG`/`NARRATE_FFPROBE` and prefers that Python. A full Python (not the embeddable zip) because the speech engine needs `venv` + pip.
- **2026-10-19 · Editor is track-based with selection-first editing.** One track per kind of edit (Video, Zoom, Speed, Blur, Words) on one time scale; drag selects a stretch, a floating toolbar (and C/Z/S/B keys) acts on it, clicking a block opens it in the inspector. Replaced the modal "…from here / …to here" buttons and the long settings scroll, which the owner found hard to understand. Settings live in an icon rail (Style, Camera, Sound, Transcript, Smart, Export); every control explains itself on hover (`data-tip`).
- **2026-10-19 · Platform shapes export at platform sizes.** 9:16 / 1:1 / 4:5 / 16:9 render at 1080×1920 etc. at the chosen quality even when the cropped screen is smaller; previously a 1080p vertical came out 738×1312. Exports use every CPU core and offer 30 or 60 fps (social presets default to 30, about twice as fast).
- **2026-10-19 · Share links on the owner's own Cloudflare R2**, hand-signed SigV4 PUTs (no AWS SDK), secret encrypted with the OS keychain via safeStorage, never sent to the renderer.
- **2026-10-20 · The product is called HomaCapture** (Tassy's name; "narrate" was the working name). Repo renamed to `Tassyomah/homacapture` (GitHub redirects the old URL), product name, window title, UI copy, installer file name and landing page updated. Kept on purpose so nothing of hers breaks: recordings folders (`~/Movies/Narrate`, `Videos\Narrate`), the speech-engine and encoder cache folders, the `NARRATE_*` env vars, `window.narrate`, the recorder file names and the `appId` (so the installer upgrades the existing install in place). Electron keys userData by product name, so `sharing.json` is copied from the old `Narrate` userData folder on first start.
- **2026-10-20 · Computer sound on macOS via a small Objective-C ScreenCaptureKit helper** (`recorder/mac/sysaudio.m` → `homacapture-sysaudio`, built by `npm run build:sysaudio`, shipped in resources/recorder/mac). Objective-C, not Swift, because the Command Line Tools on her Mac ship a Swift compiler that cannot load its own SDK (duplicate SwiftBridging module map); clang has no such problem and needs no Xcode. 48 kHz stereo float WAV, first-buffer host time = CLOCK_UPTIME_RAW = `t0System`, gaps zero-filled, so the shared finalize/editor path is unchanged. Self-test: 880 Hz 1.5 s beep came back 880 Hz, 1.51 s, onset 0.17 s after `afplay` launch. Level follows the Mac's output volume.
- **2026-10-27 · On macOS the microphone is recorded by a native helper, not ffmpeg** (`recorder/mac/micaudio.m` → `homacapture-mic`, AVCaptureAudioDataOutput, 48 kHz mono float32 WAV, first-buffer host time as t0, gaps zero-filled like `sysaudio.m`). Measured on her M-series MacBook Pro: ffmpeg's avfoundation audio input kept ≈93 % of samples alone and only ≈40 % while the same process captured the 3K screen, so every Mac voice track came out short. ffmpeg stays as the fallback if the helper is missing. Same day: Smart Director `analyze` crashed on any recording with clicks (`t` vs `c` in the highlight score), fixed.
- **2026-11-02 · Upload + automatic first edit ("content engine", Tassy's reference: Chiamaka's Claude-edited talking heads).** `import --src` (common.py, both platforms) turns any video into a project shaped like a recording (`source: "import"`, upright H.264 screen.mp4, mic.wav, no cursor); on macOS `homacapture-face` (Vision) stores the speaker's face as `focus`. The editor auto-edits uploads once a transcript exists (`renderer/autoedit.ts`): cuts fillers + pauses > 0.55 s with air either side, punch-ins (`ManualZoom.snap`, hard cuts in/out) on every other sentence, kinetic text (`TextPop`, Text lane, coral pops / paper title card) from a local key-phrase picker, bold captions, full-bleed framing. Everything stays an ordinary editable instruction; "Auto-edit again" only replaces items whose id starts with `auto-`. Next: let Claude pick the phrases and edit a selected stretch on request.

## 2026-11-02 · Five CapCut features
- **Caption styles:** Box (coral block behind the spoken word), Karaoke (words light up as said) and One word (single big word popping in) join Minimal and Bold. The social styles show 4 words at a time (6 on landscape), breaking at punctuation. Flat shapes and soft text shadow only, no outlines.
- **Sound effects:** whoosh peaking on every zoom/punch-in and B-roll, pop on every text. Synthesised by `scripts/make_sfx.py` into `video/sfx.ts` as data URLs: no samples, no licence, no Content ID risk. Smart edit turns them on.
- **Music + auto-duck:** one track per project (`media/`), looped, dips to 28 % around every spoken word that survives the cuts, 0.35 s ramps, fades in/out. A note points to the YouTube Audio Library (EP1 Content ID lesson).
- **B-roll:** pictures or clips over a selected stretch (range toolbar "B-roll", key R), own lane. Full screen (pictures drift Ken Burns style) or Card (above the face on vertical, beside it on landscape). Non-MP4 clips are converted on add.
- **Remove / blur background (macOS):** `homacapture-matte` (Vision person segmentation, temporally smoothed) between two ffmpeg pipes makes `screen.cutout.webm`, VP9 with alpha, 30 fps, long side ≤ 1920. Behind the speaker: blurred copy, brand colour or a picture. Made once on request (~0.5× real time on the test clip).

## 2026-11-06 · Editor rebuilt so it works the way CapCut feels (inspiration, not a copy)
Tassy: "capcut is more intuitive and easy to use", "I want a lot of those capcut editing features in a way I don't have to pay for capcut ever again", no templates or image generation. Full CapCut study: Inspiration Board card insp-20261106-capcut.
- **Layout:** left rail + drawer = what you can add (Media, Text, Stickers, Audio, Captions, Effects, Brand, Smart); right panel follows the selection (nothing selected = Video); timeline full width at the bottom with Split, Duplicate, Delete, Freeze.
- **Direct editing (`Direct.tsx`):** items in the composition carry `data-hc-item`; a layer over the Player finds them where they really are, so click selects, drag moves with centre guides, corners resize, the handle rotates. One undo step per gesture.
- **Timeline shows the finished video:** removed parts close up with a joint that brings them back. Items still store source seconds; only the drawing maps to output time. Blocks drag and trim; overlapping items stack in rows.
- **In-line clips (`InsertClip`):** clips, pictures, freeze frames and processed pieces play in the main line. Each has a private time slot `v` past the end of the recording, so items placed on it use the same source-time model. Versions keep only clips inside what they keep.
- **New free tools:** split, duplicate, freeze, reverse, smooth slow motion (minterpolate), stabilise (deshake; this ffmpeg has no vidstab), green screen (chromakey to png or VP9 alpha), voice changer, clip and overlay in/out animations, overlay shapes, blend, opacity, movement keyframes, fonts, text colour and background, brand kit (saved per app), timeline zoom, right-click menu, real-frame look tiles.
- **Not supported yet:** dragging a piece of the main recording to a new position (clips can move; main pieces split, trim and delete). Captions do not run over added clips.
